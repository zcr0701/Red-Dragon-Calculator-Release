Release Notes · v1.6.2

红龙贼计算器 v1.6.2

牛池（乐队经理）也自动读取——像 v1.6 认识卡组一样 · 进对局自动勾选牛池

v1.6 / v1.6.1 已经能从炉石进程内存自动识别卡组并重建牌库；v1.6.2 把最后一块手动环节也自动化——牛池（侧栏选牌）直接从内存读取并自动勾选，配合日志实时细化，开对局即算，无需再手动选牛池卡。

1新增：牛池自动读取（内存反射）

牛池数据不再依赖日志 SETASIDE 事件兜底，进对局命中卡组的同时直接从炉石进程内存读出牛池。

① 读取链路

  • 复用 v1.6.1 的原生注入组件（inject.exe + mem_deck_probe.dll），读取路径为：
  • CollectionDeck → m_sideboardManager → m_sideboards（Dictionary<long, SideboardDeck>）→ 每个 SideboardDeck（继承自 CollectionDeck）的 m_slots 槽位；
  • JSON 输出新增 sideboards 字段：每个元素对应一张带牛池的卡（如 乐队经理精英牛头人酋长）的牛池卡牌列表，无牛池的卡组为 []。

② 自动勾选

  • 命中卡组时，牛池卡名在勾选选项内（幻舞龙 / 转舞龙等 OTK 相关牛池）即自动勾选，替代「未检测到牛池」时的默认三张兜底；
  • 防重保护：仅对局首次命中套用一次，之后手动改牛池勾选不会被覆盖；
  • 池中卡不在勾选选项（非 OTK 牛池）时自然跳过，不误改用户选择。

2日志 SETASIDE 实时细化仍保留

内存牛池是「开局即知的静态配置」，日志检测是「对局中的实时变化」，两者互补。

环节内存读取Power.log 日志
牛池数据开局即读出完整牛池，自动勾选SETASIDE 事件实时跟踪已从牛池选走的卡，对应取消勾选
静态配置卡组 / 英雄卡 / 牛池（m_sideboards）—
实时对局状态—手牌 / 场面 / 水晶 / 疲劳 / 实体追踪
  • 结论：内存读取无法替代 Power.log 解析——它只能拿静态卡组配置（含牛池），实时对局状态仍靠日志；两者各司其职，共同构成「全自动」体验。

3实测

实测：运行中炉石读取「四随苔丝贼」卡组，牛池正确读出 [ETC_079（乐队经理）, SCH_352（幻觉药水）, SCH_352] 等真实卡池，勾选与对局内牛池一致。
