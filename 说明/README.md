## 运行方式

### C++ 统一入口（GUI 自动使用，找不到 exe 时回退纯 Python）

- GUI 计算时若存在 `代码/red_dragon_calculator.exe`，beam 束搜索与双向符号链都走 C++ 核心（实测约 3~5 倍加速，结果与 Python 逐条一致）；找不到则自动回退 Python 引擎。
- 重新编译：

```powershell
代码\build_core.bat
```

- 命令行直接调用（stdin 喂 JSON 局面，stdout 出 JSON 结果；PROGRESS/FOUND 实时进度走 stderr）：

```powershell
Get-Content 局面.json | 代码\red_dragon_calculator.exe --json
```

- `--python` 透传：把后续参数原样交给 Python 解释器（宽字符命令行，中文路径不乱码），用于 OCR/存档/公式表等仍由 Python 负责的部分：

```powershell
代码\red_dragon_calculator.exe --python 代码/red_dragon_calculator.py --sync-archive
```

### 命令行（不需要 GUI 依赖）

```powershell
# 红龙路径计算：给定手牌，双向符号链（反向链验证+子链拼接）搜索可达路径
python 代码/red_dragon_calculator.py --hand "狐人老千,斯卡布斯·刀油,鲨鱼之灵,晦鳞巢母" --search

# 束搜索模式（默认关闭，需显式加 --beam）
    python 代码/red_dragon_calculator.py --hand "..." --search --beam --beam-width 2000

# 关闭反向搜索时的正向自动挖掘（默认开启；会额外跑一次束搜索兜底）
python 代码/red_dragon_calculator.py --hand "..." --search --no-forward-mine

# 从 OCR 文本重建手牌（支持 --text / --file）
python 代码/rebuild_hand.py --text "手牌中(9)`n0 狐人老千`n4 鲨鱼之灵"

# 计算前自动查重（相同局面直接输出历史路径，不再重算）；计算后自动归档
python 代码/red_dragon_calculator.py --hand "..." --search

# 把局面存档提交并推送到云端（GitHub 仓库）
python 代码/red_dragon_calculator.py --sync-archive
```

主要参数见 `python 代码/red_dragon_calculator.py --help`。

### 图形界面（需要 PyQt5 + PaddleOCR）

```powershell
python 代码/ocr_region_gui.py
```

界面支持框选截图区域、选择牛头人酋长剩余卡池（舞动全场 / 幻觉药水 / 生命缚誓者阿莱克丝塔萨）、查看初始状态摘要；顶部「手动输入」按钮可展开手牌栏 / 战场（随从栏）/ 当前效果三个输入区，复用正则规则解析后直接开始计算；「beam模式」复选框默认不勾选。计算结果会写入 `代码/logs/red_dragon_all_paths_时间戳.txt`。

自动挖掘已从默认流程移除（GUI 复选框删除）：默认只跑双向符号链+子链。需要实验验算时可命令行 `--forward-mine` 启用（束宽默认 3000）。

### 实时读取：HDT 插件（默认数据源，2026-08-05 加入）

数据源切换：弹窗顶部「数据源」单选——**HDT插件（默认，推荐）** 直接读取 HDT 插件导出的对局
状态，无需框选截图区域、无需 PaddleOCR；「日志读取」为 Power.log（hslog）备用方案，
「OCR识别」保留旧方案作兜底。

前置条件（本机已满足）：

- HDT 已安装（`%LOCALAPPDATA%\HearthstoneDeckTracker\app-*\`），插件
  `RedDragonStateExport.dll` 已放到 `%APPDATA%\HearthstoneDeckTracker\Plugins\`
  并已在 `plugins.xml` 中启用（HDT 启动时自动同步到 app 目录并加载）；
- 插件每 0.5s 把对局状态写入 `%APPDATA%\HearthstoneDeckTracker\red_dragon_state.json`
  （可用环境变量 `RED_DRAGON_STATE_PATH` 覆盖路径，两侧需一致）；
- 对局中需 HDT 保持运行；首次使用请先启动 HDT 一次确认「选项 → 追踪器 → 插件」里
  红龙计算器状态导出 已启用。

重新编译插件（本机已装本地 .NET SDK 到 `C:\Users\22501\.dotnet`）：

```powershell
代码\hdt_plugin\build.ps1
```

命令行用法：

```powershell
# 打印最新对局快照（JSON）
python 代码/hdt_reader.py --once

# 持续跟随对局状态
python 代码/hdt_reader.py --watch

# 输出 rebuild_hand 文本格式 / 指定状态文件
python 代码/hdt_reader.py --once --text
python 代码/hdt_reader.py --state-file <路径> --once

# 直接用 HDT 对局状态跑搜索（无需 --hand/--deck/--mana）
python 代码/red_dragon_calculator.py --from-hdt --search
```

读取内容与机制：

- **手牌 / 场面 / 水晶 / 法力**：字段级精确（CardID、当前费用含刀油/伺机/腾武减费、
  随从攻血与关键词），法力 = `RESOURCES - RESOURCES_USED + TEMP_RESOURCES`；
- **完整牌库**：HDT 用已导入卡组 + 揭晓实体计算剩余牌库（`remaining_deck`），
  未揭示的牌也能给出中文名，优于 Power.log 的"仅已揭示卡"；
- **当前效果**：优先按场上附加效果（enchantment）实体实时检测（伺机待发/狐人老千/刀油/
  骨刺/鲨鱼之灵），无实体时回退到出牌事件计数；
- **殒命暗影**：按 `GHOSTLY` tag 标记手牌位置；
- **对手信息**（额外字段 `opponent`）：手牌数/牌库数/已打出的牌/奥秘数/场上随从；
- 本机玩家由 HDT 直接给出，无需离线缓存账号匹配。

### 备用数据源：Power.log（hslog 解析，2026-08-05 加入）

- 炉石安装目录（`F:\Hearthstone`）`Logs` 下每个会话目录里有 `Power.log`；
- 依赖库：`pip install hslog`（在运行 GUI 的 paddleocr_env 环境里已装好）。

```powershell

# 持续跟随最新对局（对局状态变化时打印）

# 输出 rebuild_hand 文本格式 / 指定日志文件

# 更新 CardID → 中文名映射（首次需联网下载卡库）

```

读取内容与机制：

- **手牌 / 场面 / 水晶 / 法力**：字段级精确（CardID、当前费用含刀油/伺机/腾武减费、随从血量），
  法力 = `RESOURCES - RESOURCES_USED + TEMP_RESOURCES`；
- **当前效果**：按“打出事件 + 消耗规则”计数（伺机待发/狐人老千/刀油/骨刺），中途启动时用附加效果实体兜底补种；
- **殒命暗影**：按 `GHOSTLY` tag（785）标记手牌位置；
- **本机玩家判定**：优先用 `%LOCALAPPDATA%\Blizzard\Hearthstone\Cache\Offline\offlineData_*` 的账号
  hi/lo 匹配 `CREATE_GAME` 的 `GameAccountId`，兜底用“牌库已知卡牌启发”；
- 玩家名绑定沿用 hslog 的换牌选择包逻辑（本机显示为 `UNKNOWN HUMAN PLAYER` 占位）。

已知边界：

- **牌库只含“已揭示”的卡**：Power.log 不会在开局直接给出整副牌（和 HDT 一样靠导入卡组解决），
  所以 `deck` 里是当前已揭晓的牌库卡；抽牌相关计算如需完整牌库，可后续加卡组文件输入；
- 对局结束（`STATE=COMPLETE`）后快照标记 `game_over`，GUI 不再推送；
- 日志解析单行失败（如新版本新增 tag）会自动跳过并计数 `line_errors`，不影响整体。

## 当前已确认的状态（截至 Codex 对话 2026-08-03）

- 计算器以"双向符号链 + 子链库（含长距离离散骨架）"为主，另带独立的正向 beam 束搜索（默认不勾选、束宽 2000）。
- 双向符号链搜索范围已修复：设置「搜索龙数上限 6 / 下限 4」时会依次搜索 6、5、4（此前 bug 导致只搜下限 4，5 龙线路被整体跳过）。
- 反向符号链升级为「双向符号链证明」：前向从初始局面按束展开，反向从目标龙数反推尾链（直出 / 暗影施法者复制 / 暗影步回手 / 舞动回收 / 药水复制 / 牛头人发现 / 骨刺·伺机铺垫），在前沿状态处拼接后经反向验证确认——像证明数学题一样两头向中间凑。
- 模板已拆分为子链库（`build_template_subchain_library()`）：从第一张红龙处把模板切成「起手段 / 尾段」，97 条起手段 + 37 条尾段，供双向引擎在生成前向候选链和反向尾链时直接复用拼接（例：`鱼狐刀暗(刀)牛`、`鱼刀刀龙`、`鱼狐刀牛(舞龙)晦步(刀)刀暗刀` 均可在子链库中找到）。
- 起手段子链已作为「前向引理」真正参与搭积木：①直接搭到初始局面；②引理状态再搭第二条引理；③束搜索前沿状态 + 短引理跳接（束宽可能剪掉的延续分支用已证结论跳过去）。引理适用性检查支持「预启动跳过」（如鲨鱼已在场上则不再收其手牌与费用，等价于开局省 4 费），最后仍经反向验证确认。实测 8 水晶场景 113 次引理尝试、161 个引理状态。
- 幸运币与伪造的幸运币在计算中等价（同为 0 费 +1 法力）：需求匹配、动作匹配、存档签名三处都按合并计数；并自动生成「币币鱼」（双币前置 + 鲨鱼之灵开头）等开手子链（实测 65 条）。引理按「边界约束契合度」排序：手牌需求占比高、约束少、链短的优先尝试。
- 性能优化（2026-08-03，对应调研文档第 7 章）：①手写轻量克隆替代 `copy.deepcopy`（原先占 ~77% 运行时间）；②CDCL 式跨链冲突学习（`step_memo`：同一局面同一动作失败/成功只算一次，实测 378 次冲突剪枝 + 863 次子链复用）；③尾链费用档案缓存 + 候选匹配 Counter 预计算；④按参数缓存尾链/子链库/符号链构建结果；⑤前向探索只卡搜索上限、自动挖掘摸到搜索下限即停。实测：殒命暗影 4/2 场景反向 5→3 从 60s → 13.1s（4.6×），8/8 场景双向 6→4 从 101s → 23.3s（4.3×），结果完全一致。
- 符号推理补漏（2026-08-03，对应调研文档第 8 章）：**舞动全场回收建模修正为“全场随从回手为 1 费复制体”**（此前符号层只回收红龙一张，导致多轮舞动结构漏算）；新增“刀油引擎·舞动全回收链”家族（鲨鱼+多张 1 费刀油叠减费，无需狐人老千/硬币，开局轮+中轮回+收尾轮自动组合）。实测用户 8 水晶样例纯反向链 0.1s 推出 9 龙/144 伤害（此前漏算、beam 需 171s 才挖到），完整 10→3 仅 0.2s；旧场景回归更快（8/8 18.1s、殒命暗影 10.7s）。
- 双向/挖掘定位澄清（2026-08-03，调研文档 8.5 节）：双向拼接+自动挖掘是“模板链库打不到搜索下限时才启动的覆盖性兜底”（触发条件 `best < min`），不是加速器——模板命中时开/关均为 0.1-0.5s，模板不中时开启才会花十几秒补漏。殒命暗影 3 龙线路已补进链库（币币[殒]鲨狐刀牛舞龙晦步刀暗刀舞重铺三龙链），该场景开/关现同为 0.09s。
- 机制分层（2026-08-03，调研文档第 10/11 章）：**双向链+子链计算**与**beam 收束计算**是两种模式，分开配置——GUI 提供「双向算子深度」（默认 **5**）与 beam 独立面板（束宽默认 **3000**、算子深度默认 **25**，默认不勾选）。**双向算子深度的语义**：最多连续几步是纯算子真实模拟，之后必须用子链/引理拼接（引理可在第 1..5 任意步拼接，视前提是否满足）；前向阶段已改为「算子展开 与 引理拼接 交错」。**引理应用带数学引理式前提**：资源需求（含硬币等价）、费用可行性、目标契合（增益不超搜索上限），以及**殒命暗影替代前提**——子链需要两张同名法术副本时，手牌「一张本体 + 一张殒命暗影」即可成立（实测：1舞+1殒命→可应用，2舞无殒命→可应用，1舞无殒命→拒绝）。新增**长距离离散子链库**（里程碑骨架，允许中间间隔）：双舞全回收骨架（5+龙：牛(舞,龙)→…→舞→…→舞[殒]）、刀油叠费引擎、暗施双龙复制、殒命双币开手、晦鳞回收轮、双暗影步回龙等 8 条，用于反向链验证排序与双向拼接候选优选。beam 启发式升级为「按当前龙数分桶 + 回收/复制/叠费潜力」，用户 9 龙样例在束宽 3000、深度 24 下可搜到 9 龙（9 龙线路最短 23-24 步，深度 25 默认已够）。
- beam 伤害优先（2026-08-03，调研文档第 12 章）：**“龙数不重要，伤害才重要”**——束内按（潜力,伤害,法力）排序 + 每桶伤害冠军保护 + 同龙数按伤害保留 + 结果按伤害排序 + “鱼先于龙”骨架奖励。实测用户 9 龙样例（束宽3000/深度25）输出 **10龙/160、9龙/144、8龙/128、7龙/112**，伤害模式完全符合预期。同时修复模型一致性：暗影施法者/幻觉药水复制体统一为 1/1（原出牌路径保留了原血量）；搜索结果后输出**计算总耗时**；路径上限移入 beam 面板、默认 **1M**。
- 费用表示归一化（2026-08-03，调研文档 12.4 节）：状态指纹的卡牌键统一按**当前费用**归一（原生 1 费与 temp 1 费不再视为不同状态）——此前 GUI 重建状态（原生1费）与测试状态（temp1费）玩法等价但指纹不同，导致 beam 走不同分支：GUI 只搜到 8 龙/128，归一化后与测试一致，输出 **10龙/160、9龙/144、8龙/128、7龙/112**。
- beam 结果反推子链（2026-08-03，调研文档第 13 章）：把 beam 搜出的 10龙/160、9龙/144 按舞动回收切成轮次参数化，新增链家族“**刀油引擎双舞步龙重铺链**”（R1 鲨刀刀龙暗(龙)龙步(龙)龙刀舞+3、R2 鲨龙龙晦龙暗(龙)刀舞+3、R3 鲨晦[刀]龙×N），并新增 4 条长距离离散骨架（步龙回手续龙、鱼先于龙、鱼晦龙收尾轮、双舞+步龙重铺）。实测**不开 beam/不开挖掘**：纯双向符号链 10→1 仅 **0.77s** 搜出 10龙/160×3 + 9龙/144；主流程 0.56s 直达 10 龙。可继续设计的子链结构见调研文档 13.3 节（药水全复制轮、伺机骨刺窗口、单步双龙循环、牛药龙发现轮、目标相关骨架表、混合回收轮等）。
- 4水晶/4法力无骨刺场景反推（2026-08-03，调研文档第 14 章）：beam 搜出 2龙/32、1龙/16，但链库只有带骨刺的三龙版。新增“**殒命双币牛舞龙晦步刀重铺链**”（target 1-3，第一轮 币币[殒]鲨狐刀牛(舞,龙)晦步刀暗施(刀)刀舞 + 收尾轮直出/牛药水/暗施双龙/暗施三龙变体）。实测**不开 beam/不开挖掘**纯双向符号链 0.24s 搜出 2龙/32、1龙/16×2，与 beam 一致。
