# 红龙贼计算器：纯束宽搜索计算流

> 版本基准：2026-08-06 纯束宽重构（彻底移除 MCTS 与子链库，代码精简）。

## 0. 数据流

```text
Power.log -> hslog 增量解析 -> snapshot（hand/board/mana/effects/...）
        -> engine.build_payload -> JSON payload -> red_dragon_engine.exe --json（stdin）
        -> 解析 stdout JSON -> results 列表 -> GUI 展示 / 写入 logs/
```

输入参数（GUI/JSON）：`min_alex`、`max_alex`、`depth`（默认 100）、`max_paths`、
`threads`、`time_budget_sec`（默认 3，硬时限 ≤3s）、`heuristic`（默认 6）、
`wide_width` / `wide_widths`（默认单路 {1100}）。

## 1. 状态、动作与奖励

- 状态 `s`：手牌 / 战场 / 牌库 / 水晶法力 / 减费层 / 牛池 / 路径（`State`，
  路径为共享写时复制，克隆 O(1)）；
- 合法动作 `A(s)`：`generate_successors` 枚举（费用可行、栏位、目标、连击、发现；
  领域剪枝：牌库未知时抽牌类法术不可枚举）；
- 转移 `T(s,a)`：`play_card_base` + `apply_search_effect`（规则与旧版逐条对齐，
  常见路径不再重复克隆状态）；
- 目标：**最高伤害**（鲨鱼在场每龙 16 伤）。

## 2. 纯束宽主搜索

- 从初始局面做全深度束搜索（按龙数分桶保留蓄力分支 + 启发值冠军兜底，
  去重键 = 状态哈希×龙数），时间预算到时返回各龙数最优路径；
- 宽束通道内部并行展开 + 按 key 分片并行合并（同 key 必同片，去重不冲突）；
- 默认单路束宽 1100（小局面 48 深线与大局面 160 深线的折中），
  `wide_widths` 可配多路；
- 硬时限 ≤3 秒：宽束循环内每 512 次展开细粒度检查预算，超时误差几十毫秒；
- 实测本机吞吐约 10 万展开/秒（分配/内存带宽受限，并行与多进程不缩放）——
  160 深线需 ~24 万展开（约 3.5s），大部分局面 1~2 秒出结果。

## 3. 启发函数（默认 H6 组合加权）

束内保留评分 = 当前伤害 + 启发函数值。启发函数库 0~15 可切换：

- H6（默认）**组合加权** = 0.6×瓶颈模型 + 资源求和 + 路径里程碑；
- H1 **瓶颈模型**（Liebig 最小因子律）：可达龙数 ≈ min(① 龙源数, ② 回手容量,
  ③ 法力可负担轮数)；
- H2 资源求和 / H3 伤害上界 / H4 法力阈值 / H5 回手容量 / H7 瓶颈平方 /
  H8 路径里程碑 / H9 几何平均 / H10 阈值阶梯 / H11 行动自由度 /
  H12 回收放大 / H13 协同密度 / H14 容量管理 / H15 软瓶颈。

实验对比（3 局面 × 16 启发 × 2 模式）：H1/H7 总伤害并列第一（384），H6 次之（376）
且十龙 160 深线最稳；纯束宽与 MCTS+束宽（迭代 50）结果完全一致、纯束宽更快。

## 4. 路径验证（`--verify`）

`red_dragon_engine.exe --json --verify` + `replay_path` 数组：逐动作重放
（同名目标实例做回溯尝试），报告剩余法力/龙数/伤害，用于核对最优路径可复现性。
