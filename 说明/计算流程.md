# 红龙贼计算器：MCTS + 束搜索模拟计算流

> 版本基准：2026-08-05 重构（删除双向符号链证明与旧 beam 束搜索，
> 计算改为 MCTS + 束搜索模拟 + 瓶颈模型启发；2026-08-06 完全放弃子链库，
> 改用简单启发函数）。

## 0. 数据流

```text
Power.log -> hslog 增量解析 -> snapshot（hand/board/mana/effects/...）
        -> engine.build_payload -> JSON payload -> red_dragon_engine.exe --json（stdin）
        -> 解析 stdout JSON -> results 列表 -> GUI 展示 / 写入 logs/
```

输入参数（GUI/JSON）：`min_alex`、`max_alex`、`depth`、`max_paths`、
`iterations`（每步 MCTS 迭代数 N）、`beam_width`（模拟束宽 B_sim）、
`sim_depth`（模拟深度上限）、`explore_c`（UCB1 探索常数 C）、
`games`（搜索局数上限）、`threads`（根并行线程数）、
`time_budget_sec`（总时间预算）。

## 1. 状态、动作与奖励（问题形式化）

- 状态 `s`：手牌 / 战场 / 牌库 / 水晶法力 / 减费层 / 牛池 / 路径（`State`）；
- 合法动作 `A(s)`：`generate_successors` 枚举（费用可行、栏位、目标、
  连击、发现；领域剪枝：牌库未知时抽牌类法术不可枚举）；
- 转移 `T(s,a)`：`play_card_base` + `apply_search_effect`（与旧版规则逐条对齐）；
- 奖励：**伤害优先**（实现为伤害×100 + 龙数，鲨鱼在场每龙 16 伤），
  关心整个序列的总伤害与总龙数；束内保留评分 = 当前伤害 +
  瓶颈可达龙数×16（上限式潜力，避免高伤害贪心把蓄力线剪掉）。

## 2. MCTS 主流程

每步真正决策时，以当前状态为根跑 `iterations` 次迭代，然后选择
**访问次数最多**（次按平均价值）的子动作执行，进入下一状态，直到游戏结束。
每次迭代四步：

1. **选择（Selection）**：沿 UCB1 下降，直到非完全展开节点或终止状态
   （UCB = Q + C·sqrt(ln N(parent)/N(child))，Q 按奖励上限归一化到 [0,1]）；
2. **扩展（Expansion）**：从未尝试动作中随机选一个，创建子节点；
3. **模拟（Simulation）**：从新节点用**束搜索**快速模拟到深度上限
   （`sim_depth`，默认 8 层），束内按
   `当前伤害 + 瓶颈可达龙数×16` 排序保留 `beam_width` 条；
4. **回传（Backpropagation）**：把模拟得到的奖励沿路径回传（visits/total）。

单局游戏 = 反复执行上述决策直到无法行动 / 达到 `max_alex` / 深度上限；
`games` 局根并行（多线程），各局独立 RNG，结束后合并各龙数最优路径。

### 根级宽束模拟通道

仅靠窄模拟束（B_sim 5~10）在有限时间内看不到 25 步以上的深线
（如 10 龙/160 伤需要“晦鳞提前打回费 + 多次舞动重铺”的蓄力走法）。
因此另开一个与 MCTS 游戏并行的**根级宽束模拟线程**：从初始局面做一次
宽束（默认 ~1600~3000）、全深度的束搜索模拟，沿用旧 beam 的
"总分 = 伤害 + 简单手写子链分 + 离散路径分、按龙数分桶、瓶颈冠军兜底、键含龙数"，
保证深线能被发现；其结果与 MCTS 游戏路径合并后输出。

## 3. 瓶颈模型启发函数（简单启发，完全放弃子链库）

红龙 OTK 每轮循环 = 打出 1 条龙 + 1 次回手。能再打多少条龙，不取决于资源总和，
而取决于最紧的那条约束（Liebig 最小因子律）：

```text
可达龙数 ≈ min(① 龙源数, ② 回手容量, ③ 法力可负担轮数)
```

- **① 龙源数**：手牌龙 + 场上龙（回手后重打）+ 暗影施法者数（可复制龙；
  鲨鱼在场或手牌时每张暗施 ≈ 2 个龙源）；
- **② 回手容量**：单体回手（暗影步/腾武）+ 整场回手（舞动/药水/战略转移）×3；
  刀油 + 单体回手 = 可再生引擎（近似无限，+15 封顶）；殒命暗影可变为回手法术
  （打五折计入，需先打出一张法术）；
- **③ 法力可负担轮数**：法力是阈值型资源（9 费能打 1 条龙，8 费打 0 条）；
  先估最便宜龙的有效费用（含手牌刀油先打出的减费潜力），
  再按“每轮 ≈ 龙费 + 回手费”估算可支撑几轮。

三个约束各自独立计算再取 min，修复了“资源求和”启发函数的三个缺陷：
假高分（回手多但无龙 = 0）、无交互（回手不与龙联动）、法力线性化（阈值化）。
束内保留评分 = 当前伤害 + 可达龙数×16（可达伤害上界）。

## 4. 参数与优化技巧

- `iterations`（默认 400）：每步决策预算，越大收敛越好、越慢；
- `beam_width`（默认 8，文档建议 5~10）：模拟束宽；
- `sim_depth`（默认 8）：模拟深度上限，越大越能看到蓄力线、越慢；
- `explore_c`（默认 1.414，文档建议 0.5~2）：探索常数；
- `time_budget_sec`（默认 30）：总时间预算，局内/步内/模拟内均可中断，
  到时返回当前最优路径；
- `threads`（默认 4）：根并行，各线程独立搜索后合并统计；
- 状态复制是主要开销：去重键复用、状态键预留容量、束内状态去重防循环、
  束宽/深度上限控制模拟成本。

## 5. 路径验证（`--verify`）

`red_dragon_engine.exe --json --verify` + 输入带 `replay_path` 数组时，
逐动作重放路径（按规范名匹配后继；同名目标实例做回溯尝试，任一实例组合走通
即判定合法），报告剩余法力/龙数/伤害，用于核对计算结果与公式表的可复现性。
